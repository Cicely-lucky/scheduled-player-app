# 第 1 章 概述

## 1.1 软件简介
小云闹钟是一款基于 Flutter 与 Android 原生混合架构开发的定时任务应用。
软件核心能力是按用户预设的时间与重复规则，自动唤起设备并执行两类操作：
（1）拉起指定 URL 链接，包括 B 站深链 bilibili://video/{BVid}、淘宝深链、网页链接等；
──── 第 4 页 / 共 63 页 ────
（2）播放本地音视频文件，支持 mp3、m4a、mp4 等主流容器格式。

软件自 2026 年 8 月开始迭代，至 2026 年 9 月完成 V1.0.0 版本，主要面向以下用户群体：
· 自学者：使用定时播放功能每日固定时段听英语听力课、播放新概念音频；
· 习惯养成者：通过每日定时打开学习 App 链接，培养稳定的学习节奏；
· 老年用户：使用本地 mp3 替代系统闹钟，提供更柔和、更长的闹铃音；
· 商务人士：定时打开指定 B 站直播链接，准时进入会议或培训。

区别于系统闹钟仅能播放铃声，小云闹钟的核心差异化在于"到点直达目标内容"——
用户无需在醒来后手动寻找 App 与视频链接，应用已经按计划打开并定位到目标页面。

· 下次触发时间倒计时（HH:mm）；

· 点击进入详情页。

### 2.1.2 调度引擎子模块
功能编号：FR-010
功能名称：双链调度
功能描述：到点触发时分两路并发执行：
（1）Dart 后台 isolate 路径——使用 android_alarm_manager_plus 触发，
在子 isolate 中执行 check() 方法，扫描到期任务，调用 MethodChannel 通知原生层；
（2）原生 AlarmManager 路径——使用 setAlarmClock 或 setExactAndAllowWhileIdle 注册系统级闹钟，
触发 PlaybackReceiver 广播，广播内拉起前台服务执行播放。

功能编号：FR-011
功能名称：重复规则计算
功能描述：支持以下重复规则，下次触发时刻自动推算：
· 每天：每天同一时刻；
· 每周一/二/.../日：每周指定周几的同一时刻；
· 指定日期：仅在该日期触发一次。

功能编号：FR-012
功能名称：自愈重排（双链解耦）
功能描述：V1.0 版本特性。每次任务触发后，无论 Dart 链是否成功执行，
原生 AlarmManager 链都会自动计算并注册下一次闹钟。该机制使双链解耦：
即使 Dart 后台 isolate 因 MIUI 杀进程而无法拉起，原生链仍能保证后续触发。

## 2.2 非功能需求

### 2.2.1 性能需求
1. 调度精度：误差不超过 ±60 秒（Dart 链）；不超过 ±5 秒（原生链）；
2. 启动时间：冷启动至首页可见不超过 2 秒；
3. 内存占用：前台运行时不超过 80MB；
4. CPU 占用：空闲时不超过 1%（不含系统进程）。

### 2.2.2 可靠性需求
1. 后台存活率：MIUI 14/15/16 设备开启"三件套"权限后，7×24 小时不漏触发；
2. 异常自愈：单点故障不导致全局调度失效；
3. 数据持久化：任务数据存储于 SharedPreferences，卸载前不丢失。

### 2.2.3 兼容性需求
1. 操作系统：Android 8.0 (API 26) 至 Android 16 (API 36)；
2. CPU 架构：arm64-v8a（小米/红米主流）；
3. 主要验证机型：小米 14（Android 16, MIUI 16）；
4. 屏幕适配：360dp ~ 600dp 全宽屏（手机/平板）。

### 2.2.4 安全性需求
1. URL 协议：仅允许 http、https 与已知白名单深链 scheme；
2. 文件访问：仅访问用户通过 SAF（Storage Access Framework）授权的文件，
禁止后台静默读取其他 App 私有目录；
3. 权限最小化：只申请功能必要的权限，不申请通讯录、位置等敏感权限。

### 2.2.5 可维护性需求
1. 模块化：Dart 端按 models/storage/services/scheduler/pages/widgets 分层；
2. 命名规范：类名 PascalCase，方法名 camelCase，常量 UPPER_SNAKE_CASE；
3. 注释覆盖率：核心类与方法 ≥ 50%；
4. 持续集成：每次提交自动构建 APK 并保留 90 天产物。

## 2.3 用户场景

### 场景 1：每日英语听力
用户 Alice 是一名自学者，希望每天早上 7:30 自动播放"新概念英语第二册 Unit 4"。
操作流程：
1. 打开小云闹钟，点击底部"新建任务"；
2. 选择类型为"URL 链接"，粘贴 B 站视频链接；
3. 设置触发时间 07:30，重复规则"每天"；
4. 保存任务；
5. 次日 07:30 应用自动点亮屏幕，唤起 B 站并定位到目标 Unit 4。

### 场景 2：定时进入直播会议
用户 Bob 是远程会议参与者，希望每周一三五 9:00 自动进入 B 站直播间。

## 4.2 调度引擎模块
调度引擎是本应用的核心创新点，V1.0 版本实现了双链解耦机制。

4.2.1 双链设计原理
链 A：Dart 后台 isolate 链
· 通过 android_alarm_manager_plus 的 oneShotAt 注册；
· 触发时在后台 isolate 跑 check()，扫描到时间，调用原生播放；
· 受 MIUI 后台限制影响大，杀进程后可能被压制。

链 B：原生 AlarmManager 链
· 通过 AlarmManager.setExactAndAllowWhileIdle 注册；
· 系统级闹钟，MIUI 必须放行；
· 触发时由 PlaybackReceiver 拉起前台服务。

V1.0 改进：链 B 在触发后自行重排下一次，不再依赖链 A 活着。

──── 第 18 页 / 共 63 页 ────
4.2.2 核心 API
Scheduler.scheduleTask(PlayTask t)
  - 注册链 A：oneShotAt(nextRunAt)
  - 同步至链 B：send broadcast to UrlAlarmScheduler.schedule()

Scheduler.cancel(String id)
  - 取消链 A：cancel(int notifId)
  - 取消链 B：send broadcast to UrlAlarmScheduler.cancel()

Scheduler.syncAll()
  - 加载所有启用任务 → 链 A 全量重排 → 链 B 全量重排

4.2.3 重复规则推算
nextRunAt(PlayTask t) 函数返回 DateTime 类型的下次触发时刻：
· freq='daily'：取今天 HH:mm，若已过则 +1 天；
· freq='weekly'：从今天起 7 天内找匹配 days 的最近一天；
· freq='date'：取指定日期的 HH:mm，若已过则返回 null。

4.2.4 自愈重排（原 V1.0 增强）
UrlAlarmScheduler.rescheduleNext(item) 在每次原生闹钟触发后调用，
根据 item.freq/days/time 计算下一次触发时刻并重新注册。
即使 Dart 后台 isolate 拉不起来，原生链也能保证持续触发。

# 第 5 章 软件详细设计

## 5.1 核心算法：双链调度
双链调度是本应用 V1.0 的关键算法，目标是：
1. 单点故障不影响全局；
2. Dart 后台 isolate 拉不起来时，原生链仍能持续触发；
3. 自愈重排不依赖任何持久化层（不写 SharedPreferences）。

5.1.1 调度入口：Scheduler.scheduleTask(PlayTask t)
输入：单个任务对象。
输出：无（副作用：注册两个闹钟）。
伪代码：
function scheduleTask(t):
  if !t.enabled: return
  next = nextRunAt(t)
  if next == null: return
  // 链 A：Dart 后台 isolate
  AndroidAlarmManager.oneShotAt(
    next, 1, 'check', exact: true, wakeup: true, reschedule: true)
  // 链 B：原生 AlarmManager
  broadcast SYNC_URL_ALARMS with [{id, at, url, freq, days, time, date}]

5.1.2 check() 函数（Dart 后台 isolate 中执行）
function check():
  try:

function nextRunAt(t):
  parts = t.time.split(':')
  h = parts[0]; m = parts[1]
  switch t.freq:
    case 'daily':
      candidate = today_at(h, m)
      if candidate <= now: candidate += 1 day
      return candidate
    case 'weekly':
      for i in 0..7:
        d = today + i days
        if d.weekday in t.days and d_at(h,m) > now:
          return d_at(h,m)
    case 'date':
      if t.date + h:m <= now: return null
      return t.date + h:m

  static Future<List<PlayTask>> all() async {
    final prefs = await SharedPreferences.getInstance();
    final raw = prefs.getString('tasks') ?? '[]';
    final arr = jsonDecode(raw) as List;
    return arr.map((j) => PlayTask.fromJson(j)).toList();
  }

  static Future<void> upsert(PlayTask t) async {
    final all = await this.all();
    final idx = all.indexWhere((x) => x.id == t.id);
    if (idx >= 0) { all[idx] = t; } else { all.add(t); }
    await _save(all);
  }

  static Future<void> remove(String id) async {
    final all = await this.all();
    all.removeWhere((t) => t.id == id);
    await _save(all);
  }

  static Future<void> _save(List<PlayTask> all) async {
    final prefs = await SharedPreferences.getInstance();
    final raw = jsonEncode(all.map((t) => t.toJson()).toList());
    await prefs.setString('tasks', raw);
  }
}

## 13.1 安装与升级
**Q：安装时提示「应用未安装」怎么办？**
A：多为与旧版本包名冲突或签名不一致所致。V1.0.0 已把包名由 com.example.scheduled_player_app 变更为 com.cici.scheduledplayer，首次安装新包名版本前请先卸载旧版本；若为同包名覆盖安装失败，请确认两次 APK 来自同一 CI 流水线（签名已通过 actions/cache 固定）。

**Q：卸载后任务数据会保留吗？**
A：不会。任务数据保存在应用沙箱的 SharedPreferences 中，卸载应用时随沙箱一并清除，属 Android 标准行为。建议重要任务在卸载前截图留存。

**Q：可以用同一个 APK 给多台手机安装吗？**
A：可以。本应用无账号体系、无服务端依赖，APK 可自由分发。唯一需要注意的是每台手机都需单独授予悬浮窗、后台弹出界面、锁屏显示三项权限——这三项权限在 MIUI 上不会随 APK 一起迁移。

**Q：升级到新版本后任务会不会丢失？**
A：不会。只要包名不变，覆盖安装会保留沙箱数据。任务列表、启停状态、频次配置都会原样延续。


## 13.2 定时不触发
**Q：为什么到点后没有任何反应？**
A：按以下顺序排查：① 省电策略是否设为「无限制」；② 是否开启「自启动」；③ 任务是否处于启用状态；④ 任务频次与日期是否匹配今天；⑤ 悬浮窗、后台弹出界面、锁屏显示三项权限是否已开。其中「自启动」是最易被忽略的一项——MIUI 在应用被清理后若无自启动权限，后台 isolate 无法被拉起，两条调度链会同时失效。

**Q：链接任务播放一次后就不再触发了，是什么原因？**
A：根因是调度重排链条断裂。V1.0.0 做了两处加固：其一，check() 的重排逻辑从 try 末尾移入 finally，保证即使检查过程抛出异常也一定会补注册下一次；其二，原生链新增自愈重排——随 PendingIntent 下发 freq/days/time/date 四个字段，广播触发后由 UrlAlarmScheduler.rescheduleNext() 自行计算并注册下一次，与 Dart 链完全解耦。两条链互为备份后，单点故障不再导致整体停摆。

**Q：手机关机再开机后，闹钟还在吗？**
A：开机后 Android 会清空全部 AlarmManager 闹钟。本应用在启动时读取任务池并整体重排，因此只需在开机后手动打开一次 App（或等待系统因其他原因拉起 App），闹钟即自动恢复。

**Q：任务时间设置成「每天 07:00」，但有时会晚几分钟触发，正常吗？**
A：正常。Android 出于省电考虑会对闹钟做批量对齐（Doze/打盹模式下的时间窗），偏差通常在数分钟内。本应用使用 setAlarmClock() 注册，属于精确闹钟级别，偏差已显著小于普通 set() 方式。

**Q：为什么锁屏状态下有些手机能亮屏播放、有些不能？**

A：取决于「锁屏显示」权限是否授予。链路为：PlaybackReceiver → 启动 UrlBridgeService 转前台 → 拉起带 showWhenLocked / turnScreenOn 的 UrlBridgeActivity → 打开目标链接。缺少锁屏显示权限时，Activity 会被 Keyguard 拦截，此时会自动降级为发送通知提醒。


## 13.3 链接与播放
**Q：只能定时打开 B 站链接吗？**
A：不是。http / https 开头的通用链接都能打开，系统会通过隐式 Intent 交给默认浏览器或对应 App 处理。若需要打开其他 App 的私有深链（如某些 App 的自定义 Scheme），则需该 App 在清单中声明可被外部查询，部分系统版本还会限制包可见性，此时可能弹出选择框或无法直达。

**Q：支持播放本地文件吗？**
A：支持。任务类型可选「本地文件」，通过系统文件选择器（SAF）授权后记录 URI。注意 URI 授权在重启后可能失效，长期使用建议选择应用可长期访问的目录。

**Q：同一个链接设了两个任务，会重复触发吗？**
A：不会。播放器具备 60 秒去重窗口，同一 URL 在 60 秒内只触发一次，避免两条链路同时命中导致重复播放。

**Q：播放时能不能后台静音或只提醒不播放？**
A：可以。任务详情页可关闭「自动播放」开关，届时只发出通知提醒而不直接拉起播放。


## 13.4 性能与耗电
**Q：常驻后台会不会很耗电？**
A：不会。应用本身不申请常驻前台服务，也不做轮询唤醒；仅在闹钟触发瞬间唤醒执行，执行完毕立即释放。日常待机状态下对电量的影响可忽略。

**Q：任务很多（如 50 个）会不会影响性能？**
A：每个任务注册两个闹钟，50 个任务即 100 个闹钟条目，远低于系统上限（单应用通常 500 个）。任务列表使用 ListView.builder 懒加载，滚动流畅度不受任务数量影响。

**Q：任务数据存在哪里？会上传吗？**
A：全部数据仅保存在本机应用沙箱（/data/data/com.cici.scheduledplayer/），应用不集成任何统计 SDK，不发起任何网络请求，不含任何后台上传行为。
